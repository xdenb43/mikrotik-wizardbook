Back-To-Home over Amnezia Client

MikroTik Back-To-Home (BTH) provides remote access to a home network using WireGuard.

Amnezia Client can be used as an alternative WireGuard client with AmneziaWG compatibility features.

Architecture

Remote device
     |
     |
Amnezia Client
(AmneziaWG compatibility mode)
     |
     |
Internet
     |
     |
MikroTik Back-To-Home
(Standard WireGuard)
     |
     |
Home LAN

Important

MikroTik RouterOS currently provides standard WireGuard functionality.
It does not support native AmneziaWG server-side parameters.

Therefore, the connection uses AmneziaWG compatibility mode, where the client adds obfuscation features while preserving standard WireGuard handshake compatibility.

Configuration

1. Generate Back-To-Home configuration

Create a Back-To-Home WireGuard profile on MikroTik.

Export the client configuration:

[Interface]
PrivateKey = ...
Address = ...
DNS = ...

[Peer]
PublicKey = ...
Endpoint = ...
AllowedIPs = ...
PersistentKeepalive = 30

2. Convert configuration

Convert the WireGuard profile using online converter, e.g. https://wireguard-converter.vercel.app/

The resulting configuration can be imported into Amnezia Client.

Compatibility parameters

For MikroTik Back-To-Home compatibility, the following parameters must not be changed:

S1 = 0
S2 = 0

H1 = 1
H2 = 2
H3 = 3
H4 = 4

These values preserve compatibility with the standard WireGuard implementation used by MikroTik.

Changing these parameters switches the client into a full AmneziaWG mode, which is incompatible with MikroTik RouterOS WireGuard.

Optimized parameters

The following profile was tested on:

  • MikroTik hAP ax³
  • Back-To-Home Relay mode
  • AmneziaWG Android/Iphone clients
  • amneziawg-proxy-mikrotik container
  • mixed network conditions (LTE + Wired)

Parameter explanation

MTU

MTU = 1280

A conservative value optimized for mixed environments:

  • LTE networks
  • carrier NAT
  • WireGuard overhead
  • possible relay usage

Lower MTU reduces fragmentation risks and improves reliability on unstable mobile connections.

Junk packets

Jc = 3

Number of junk packets sent before WireGuard handshake.
Lower values reduce connection establishment delay.
Testing showed that larger values increased perceived latency during opening websites and applications. 

Jmin = 40
Jmax = 90

Defines the random size range of junk packets.

The tested results showed that:

  • very small packets increased perceived delay
  • large ranges created unnecessary overhead
  • a moderate range provided the best balance between responsiveness and traffic obfuscation

Troubleshooting

Connection works but feels slow

Try reducing Jc
Large junk packet counts increase initial connection latency.

Speed is normal but websites open slowly

Check:

  • MTU
  • relay usage
  • mobile network latency

Do not increase Jc unless required.
